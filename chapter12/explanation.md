For the representation of the sleeping processes we 
stored the sleep state in pcb-> sleep_deadline. 
When it is 0, the process isn't asleep and when it is nonzero, the process is currently asleep and should be awake (in the run queue) when it reaches the sleep deadline. 

The sleep queue structure is a circular list. It is a circular list because the tail pointer points to the head and is consistent with the queues already implemented in circular single linked lists like the proc_enqueue and proc_dequeue. If sleep_queue is 0 that means the queue is empty and if it only has one process we know that node->next = node.

We know there is no busy waiting in user space because user_delay calls user_sleep. When we call user_sleep, if the sleep deadline has not already passed, we put into the sleep queue. Then, it calls sched_block(), which will remove the process from the ren queue and perform a context switch to another runnable process, so we do not do any busy waiting. We have periodic timer interrupts that will check if the time since boot is greater or equal to than the sleeping processes' respective sleep deadlines and wake them up if so, which is implemented in sched_wake_sleeping(). In sched2.c, sched_idle() calls trap_wfi that makes the core have low activity until an interrupt arrives so cpu isn't busy waiting.
